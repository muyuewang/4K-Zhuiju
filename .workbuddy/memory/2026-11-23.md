1. GET `/v1/catalog/{id}` → 200。第201集节点的 `token` 字段是
   `av_Vm_OFGxGcdlu1TObNQUDuCxxBUaOc1bTCHe89HVhcL2CQ0K3Rmtgxyv6wLvGixhXi6J1VV7NpHYgStU4RfXlU6E`

| 结果 | 条数 | 说明 |
| --- | --- | --- |

| 201 | 1 | `token_scenario=series_intro_zero`，片头预览，地址是 jpg 不是正片 |
| 404 | 1 | `playback_line_unavailable` |

**匿名状态第201集线路里根本没有「1080P-官方K」**（登录态专属线），
普通线可播的：`红牛资源`（206）、`无水印资源`（206）、`ikun资源`（200），
其余 `极速/新浪/魔都/1080zyk/暴风` 等大多 000/403。

### 结论与修复

官方线现在要登录态。网页截图是登录 VIP 所以能播；软件无账号登录通道，
**这个门槛跨不过去，不是解析 bug**。站点策略 2026-11-18 还是
「10/10 官方线免登录可换票」，11-23 变了。

真正可修的是「用户只看到 HTTP 401、看不到原因」：
`PluginFetch.fetch()` 原先 `code >= 300` 直接抛 `HTTP $code`，
脚本的 `parseLineResolve` 根本没机会执行，服务端那句「该内容需要登录后播放」
永远到不了界面。

改为：4xx/5xx 时从 body 提取 `message`/`msg`/`error_message`/`detail`
带进 `PluginFetchException`（限 80 字符）。`validateStatus: (_) => true`
保证了 `resp.data` 在 4xx 时仍保留 body，解析失败退回原 `HTTP $code`。

## 反转：用户的「能匿名登录」是对的，官方线已修好并发版 v1.11.18

### 我上一轮错在哪

上轮结论写的是「官方线要登录 VIP，软件无账号通道，跨不过去」。
**错在把 `playback_user_session_required` 直接读成「要 VIP 账号」。**
用户一句「我记得看剧能匿名登录 你试试」点破了。

实测 `POST /v1/users/anonymous`（空 JSON body，带签名）→ **201**：

```
Set-Cookie: ai_movie_session=ums_xxx; Max-Age=31535999; Domain=kanju.ai; Secure
```

带这个 cookie 换票 → **10/10 全部 201 成功**，9 条 401 全消失。
唯一始终 404 的是「哔哩哔哩」（playback_line_unavailable），与会话无关。

**门槛是「要有游客会话」，不是「要有 VIP 账号」。**
教训：服务端错误码里的 `user_session_required` 说的是会话，不是付费账号。
下次遇到 `*_session_required` 先找匿名/游客会话端点，别直接判定要登录。

### 新增宿主能力：bootstrap 会话引导

- `PluginManifest.bootstrapRequest`（清单 `bootstrap` 字段），纳入 `_allRequests`
  走 Host/Cookie/Authorization 黑名单（防止成为脚本注入后门）
- `RemoteJsSource._bootstrapOnce()`：业务请求前自动打一次引导，
  **用 `Map<id, Future<void>>` 缓存**——不能用 bool，否则首页并发请求会在
  引导完成前发出去、拿不到 cookie。失败时移除缓存允许下次重试。
- `_fetch` 加 `bootstrap: true` 参数防递归
- `resetForTest()` 清引导与 stickyBase，供测试隔离
- 清单 kanju：`cookieJar: true` + `bootstrap: {path:/v1/users/anonymous, method:POST, bodyType:json, body:{}}`

宿主自动收 Set-Cookie、后续请求自动回送，**脚本全程碰不到 cookie**，
安全边界与既有 cookieJar 一致。会话纯内存，进程退出即丢弃。

## v1.11.18 的会话引导其实没生效 —— _sign 重建丢字段（用户复报「前几集能看、后面 401」）

### 现象与定性

用户复报：凡人修仙传官方线，前几集能播，后面 401 要登录。

`code/tools/diag_kanju_episode_gate.py` 前后集对比（同一剧 1~201 集）：
- **带匿名 cookie**：1~201 集全部 201 换票成功
- **不带 cookie**：1/2/200/201 集碰巧 201，5~180 集大多 401 `playback_user_session_required`

结论：**401 与集数无关，只与有没有会话有关**。用户看到的「前几集能看」
是免会话线路的假象，不是站点按集数放闸。别再往「VIP 门槛/集数限制」方向查。

### 上一版为什么没修好（真正的坑）

v1.11.18 加了 bootstrap 会话引导，真实设备却仍 401。诊断过程：
- 真实 Dart 宿主：`[PLUGIN] kanju 会话引导完成` 打了，但换票时 `jar` 一直是空
- Python 探针用同一 cookie 连换 13 集全通 → 差异锁定在宿主 cookie 管理
- 关键：**看剧源配了 signEntry（HMAC 签名），每个请求都过 `RemoteJsSource._sign()`**

根因：`_sign()` 在签名后重建 `PreparedRequest`（937 行）时**漏传 `cookieJar`**，
字段退回默认 false。于是 fetch 既不吸收 Set-Cookie、也不回送 Cookie ——
引导成功但 cookie 当场被这次重建丢掉。

> **这是「重建请求漏字段」类 bug 的第二次**（第一次是橘汁的 Content-Type 覆盖）。
> `_sign()` 重建 PreparedRequest 时已踩过 contentType/binaryResponse/bodyBytes，
> 这次又漏 cookieJar。以后往 PreparedRequest 加字段，**必须同时改 `_sign()` 重建处**，
> 否则所有带签名的源都拿不到新字段。

### 修复

`remote_js_source.dart` 的 `_sign()` 重建处加 `cookieJar: base.cookieJar`。

### 为什么测试没拦住（测试盲区）

`plugin_bootstrap_test.dart` 原来**没配 signEntry**，走的是不签名路径，
所以 cookieJar 不经过 `_sign` 重建，测试全绿但真机失败。
新增回归用例：给测试源加 `signEntry: 'sign'`（最小钩子原样回传），
断言带签名时引导 cookie 仍能回送。**以后 bootstrap 类测试必须覆盖签名路径。**

真实端点测试 `kanju_anonymous_session_test.dart` 也从只测第 201 集
扩成第 1/100/201 三集，修复前第 100 集就 401，修复后三集全通。
