## 数据源插件化（远程 JS 执行）落地

用户决策：走 **JS 路线**（不是评估文档里的 dart_eval），配置 JSON 放本仓库、远程加载，
且**必须用国内镜像**（否则用户拉不到）。

### 引擎选型：QuickJS（flutter_js 0.8.7）

评估文档测的是 dart_eval，两套结论**不能互相引用**。实测 QuickJS：

| 能力 | 结果 |
| --- | --- |
| JSON / 正则 / 中文 emoji | ✅ |
| `async`/`await`/`Promise` | ✅ 真能用（`await Promise.resolve(99)` → 100） |
| 宿主 ⇄ JS 双向消息 | ✅ |
| `require` / `fs` 逃逸 | ✅ 不存在 |

比 dart_eval 强的地方：null 语义正常、`Map.forEach`/`continue`/扩展方法都支持。

### 关键负面结论（决定了整个安全设计）

1. **`QuickJsRuntime2(timeout: N)` 完全无效**：`timeout: 1` 跑 `while(true){}`，89 秒后仍未返回。
2. **`Isolate.kill()` 杀不掉卡在原生 FFI 的 isolate**：kill 后 15 秒收不到 onExit，
   主 isolate 仍能 spawn 新 isolate（说明是线程泄漏而非全局冻结），后台继续烧 CPU。

→ 所以「超时打断」不能作为安全保证。改成三道前置防线：
- 装载前静态筛查 `while(true)`/`for(;;)`（`looksLikeInfiniteLoop`，会剥离字符串与注释避免误判）
- 强制入口同步，返回 Promise 直接拒绝（顺带堵住「插件自己发请求绕过 SSRF」）
- 中毒计数：超时一次换 worker，累计 2 次停用插件执行

  漏了 case，调用只报「未知宿主函数」。已补。

## 强制刷新 + 刷新入口始终可见（v1.11.9+34）

用户反馈「刷新插件只有一个源」「Windows 又没有刷新功能」。排查结论：
1. 用户机器 Windows 缓存 `C:\Users\fengxin\AppData\Roaming\4K追剧\4K追剧\shared_preferences.json`，
   键 `flutter.app.plugins.v1` 存的是 v1.11.7 的白杜旧配置（js_bdzy，2 源里 1 个 enabled=false
   → 正好 1 个源），dataSourceId 也被持久成旧值。**19 个源的配置和代码本身都是好的**：
   远端 index 带时间戳、三个镜像都返回 19 条，19 个脚本逐个下载全成功。
2. 根因是刷新用**小时级**时间戳 `ms~/3600000`，同一小时点刷新命中 CDN 缓存的旧 index，
   表现「提示已更新，源却没变」。改为 `PluginLoader.refresh({bool force})`：
   - 自动刷新（启动）force=false 用小时戳省流量；
   - 手动点按钮 force=true，用微秒戳，每次 URL 不同，CDN 必然回源。
   - `PluginSync.refresh({force})` 透传；设置页 `_onTap` 调 `force:true`。
   - 纯函数 `cacheBustStamp({force,now})` 便于测试，3 条新测试。
3. 更隐蔽的坑：设置页刷新行原来只在「pluginCount>0 或 lastError!=null」才显示。
   零源 + 静默失败（lastError 为 null）时按钮**消失**，恰好在最需要自救时没入口。
   改为始终显示；副标题改「强制拉取最新配置，忽略缓存」。移除无用 import。
版本 1.11.8+33 → 1.11.9+34，需重新打包 Windows/APK 才有 force 逻辑。

## 二轮：8 类实机问题实测与修复（v1.11.10+35）

用户实机试出：看剧只剩一条线路；电影天堂列表封面慢；非凡/猫眼/优子/起点
