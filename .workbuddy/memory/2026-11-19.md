## 01:00 搜索结果页改造：左侧源导航 + 单源分页（v1.11.15+40）

### 需求原话与三项决定

用户要求：「左侧竖排：全部、看剧、大师兄-量子、等等；可以选择看全部的搜索结果、
还是每个源的搜索结果；全部页面不好弄分页、但是选择某个源后就可以分页了」。

随后给出的三项明确决定（都已按原样实现，不要再"优化"掉）：

1. **单源页保留「来源角标」** —— 不要因为"单源页里角标是冗余信息"就删掉。
2. **「全部」页显示具体条数**（「共 386 条」），不是「搜遍 N 个源」。
3. **超时、无结果的源不显示在左侧源列表** —— 点进去必然空屏。

### 五个容易踩回去的坑

1. **去重后不能用 `_result` 按 sourceId 过滤**
   全局搜索按「名称+年份」跨源去重，去重后只留一条且只带一个 sourceId。
   若用去重结果过滤，会出现「左栏写 42 条、点进去 38 条」。
   → 必须在 `GlobalSearchProgress` 里额外保存**每源未去重的原始列表** `perSource`。

2. **分页能力不能用 getter 声明**
   项目里所有源都是 `implements DataSource`（不是 extends）。Dart 的
   `implements` 会绕过继承来的默认实现 —— 在 `DataSource` 里写
   `bool get supportsSearchPaging => true` 一点用都没有，编译器照样要求
   每个实现类补一行。→ 只能用可选**标记接口**，与既有 `SearchUnsupported` /
   `SectionedFeed` / `SourceGrouped` 同一套模式。

3. **`_srcPageSize` 必须等于 `kGlobalSearchPerSourceLimit`**
   各源搜索接口都**不返回总数**，「还有没有下一页」只能靠「本页够不够一整页」
   推断。两个常量不一致会判错：判少了吞掉真实存在的下一页。

4. **切换源不发请求**
   全部页已经把每源 page=1 拿回来了，切源只是换视图（`_perSource[id]` 直接用）。
   只有点「下一页」才打接口，且只打一个源的（几百毫秒）。
   这是「全部页不分页、单源页分页」这个设计能成立的立足点 —— 全部页翻页要让
   19 个源同时翻到第 2 页，慢且各源分页语义不统一。

5. **测试里 `find.text('看剧')` 会歧义**
   因为决定 1 保留了角标，源名会同时出现在左栏和每张海报角标上。
   测试必须用 `find.descendant(of: find.byType(SearchSourceRail), ...)` 限定。

### 实测数据（别凭感觉改）

- 左栏宽度 **134dp**（TV 176dp）。134 是平衡点：手机竖屏（≥360dp）扣掉它
  还剩 226dp，按 `kPosterTargetExtent` 能放 2 列海报；再宽就只剩 1 列，
  搜索结果退化成大图流，一屏看不到几部片。
- 不支持翻页的源实测三个：`ddys_source` / `jisu_source` / `kvm4k_source`
  （前两个 `if (page > 1) return const [];`，kvm4k 的 page=2 与第 1 页逐字节相同）。

### 交互细节（容易被"简化"掉的）

- 选中态用 `foregroundDecoration` 画 2px 左竖条，**不用 Stack** ——
  Stack 里 GestureDetector 命中区只在 child 上，竖条会变成点不到的死区。
- 选中时内容 `left: base + 2`，否则切换选中项时文字会左右跳一下。
- 页码用 `FontFeature.tabularFigures()`，否则 9→10 进位时整行抖动。
- 翻页按钮禁用态保留占位（淡色），不隐藏，否则两侧控件位置跳动。
- **翻页失败不清空已有结果** —— 用户可能正在看第 1 页，抹掉换错误页更糟，
  只在顶部加一行说明（`_srcErr`）。
- 状态行：单源 `'${源名} · 共 N 条（第 X 页）'`；全部 `'共 N 条 · M 个源有结果'`。
- 左栏底部 footNote 显示失败源数量（「N 个源无响应」），满足决定 3 的同时
  不让用户完全失去"有几个源没回来"的信息。

### 两个新踩的坑

1. **Dart AOT 会裁剪标识符，不能靠 grep 字段名验证新代码**
   `perSource` / `SearchSinglePage` / `_srcPageSize` / `totalHits` 在 `libapp.so`
   里 **0 命中**，但 `SearchSourceRail` / `PageBar` 命中 1 次。原因是 AOT 只保留
   被 `is` 检查或反射边缘用到的类名，普通字段名/私有符号全被裁掉。
   → 验证"新代码进没进去"要搜**界面文案常量**（字符串字面量必定保留），
   不要搜变量名。

2. **按 UTF-16LE 固定对齐解码会漏字符串**
   一开始把 `libapp.so` 整体 `decode('utf-16-le')` 再 `.count('上一页')` 得到 0，
   误以为代码没进包。实际是 Dart 字符串池条目在奇字节偏移上时，按偶对齐解码
   会把相邻两字符错位，整串对不上。
   → 正确做法：`so.find('上一页'.encode('utf-16-le'))` 裸字节搜索，
   不受对齐影响。
