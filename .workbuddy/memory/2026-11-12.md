## v1.10.1：三个数据源故障 + 播放器黑底黑字（已发布）

### 核心发现：Dart 的 HttpClient 不读系统代理

浏览器读 Windows 系统代理（`ProxyEnable`/`ProxyServer`），`dart:io` 的
`HttpClient` **从不读**，永远直连。这一条同时解释了「暴风封面加载不出」和
「可可影视列表加载不出」——两者网页版都正常。

**排查陷坑（重要，别再犯）**：用 Python `urllib` 探测会得到完全相反的结论，
因为它**自动读系统代理**。早期所有「暴风封面 200、可可 850，服务端没问题」的
结论都是错的。必须加 `ProxyHandler({})` 强制直连，才能模拟 App 的真实行为。

修法：`core/net_proxy.dart`，在 `HttpOverrides.global` 单点注入
（覆盖 8 个 Dio、裸 HttpClient、HlsProxy、cached_network_image 内部的
package:http、video_player）。
- 本机/内网段强制 DIRECT —— HlsProxy 监听 127.0.0.1，代理它会死循环
- 端口候选表**刻意不含 8080/1080**（本机开发服务器常占，误判比不设代理更糟）
- 认出端口后发 `CONNECT 127.0.0.1:1` 验证协议
- reg.exe 读不到时扫候选端口兜底（本环境 reg 被沙箱拦，正好验证了这条路径）

### 片库转圈：HlsProxy 把子清单当分片

片库 4K 的 master 只有 101 字节 1 个条目，实为**子清单**。旧代码一律当分片
转发 → 子清单里的相对地址以 127.0.0.1 为基址拼错 → 永久转圈。
修：识别 m3u8 递归展开 + `playlistDepth` 上限 32 + `addSegment` 去重。
实测展开 2680 条，分片 206/262144B 全正常。

## 集成新数据源 4K影视（www.4kvm.net）

### 站点定性（实测）
- Go 服务端渲染站，非 MacCMS（`api.php/provide/vod/` 实测 404）；`404 page not found` 是 Go 默认文案

- 源站国内直连不通（os error 11001），必须走系统代理

### 播放地址：前端 WASM 取址，已完整还原
站点加载 `/static/wasm/nbmovie_wasm_bg.*.wasm`，调 `build_play_url(dataid, secret_key, quality, play_key)`
生成 `/video/play?p=&v=&q=&s=&t=&k=`。逆向结论（**WASM 只是障眼法，纯 Dart 可复现**）：
- `k` = `base64(userlink 逐字节 XOR "nbmovie2024secretkey")`，空串/`'0'` 原样返回 `'0'`
- `s` = **HMAC-SHA256(key=vodId, msg="<dataid>:<ts>:<vodId>")** 取 hex 前 32 位（key 是 slug，不是那个 nbmovie 密钥）
- `userlink` 由详情页每次下发（导航栏 x-data `userlink:'...'` → `window.myuserlink`），带时间语义

### 破解路径（方法论留存）
盲爆 18 万组全失败 → 固定 `Date.now()` 做受控实验缩小依赖域 → 拦 `WebAssembly.instantiate` 拿 memory 做内存取证，
读到原文 `42058:1794455847849:ch4sn04yf` → wabt 反编译出 WAT，在 `i32.const` 里找到 SHA-256 K 表 64/64
（**编译后常量是 LEB128，`struct.pack` 找原始字节全 0 命中**）→ 给 SHA-256 压缩函数 `f17` 插桩 dump 输入块，
看到 `0x36`/`0x5c` 填充块即认出 HMAC 的 ipad/opad。

### 分页真相
- `/search?q=` 固定 20 条，**`page` 无效**（page=2/3 与第 1 页逐字节相同）→ 适配器第 2 页起显式返回 `[]`
- `/filter?classify=N&page=M` **有效**，每页 30 条，第 184 页仍有数据
- `/movie?page=2` 无效（与首页逐字节相同）

`kvmPickPlayableUrl` 按「非 VIP + 未 locked + url 是 http」挑，宁可降一档给 1080P。

## v1.10.5：根治 Windows 播放内核（Media Foundation → libmpv/FFmpeg）

### 问题
看剧源《名侦探柯南：高速公路的堕天使》网页/PotPlayer 能播，App 不能播。
实测地址 `https://hn.bfvvs.com/play/e73XXy8e/index.m3u8`：
- 清单第 5 行 `#EXT-X-KEY:METHOD=AES-128,URI="enc.key",IV=0x000…000`
- 取 key 200/16B、取分片 200/877KB，**服务端完全正常**
- `openssl aes-128-cbc` 解出 `47 40 11 10…` → 确认为 AES-128 加密的 TS
- 用户补充：**APK 能播、Windows 不能播** → 直指内核差异

### 根因
| 平台 | 内核 | HLS | AES-128 | 相对地址 |
|---|---|---|---|---|
| 浏览器 | hls.js | ✅ | ✅ | ✅ |
| PotPlayer | FFmpeg | ✅ | ✅ | ✅ |
| Android | ExoPlayer | ✅ | ✅ | ✅ |
| Windows(旧) | **Media Foundation** | 基础 | ❌ | ❌ 拼错 |

`video_player_win` 底下是 MF，三类缺陷（相对地址、AES-128、多级清单）全中。

### 改法：换内核（不是继续打补丁）
`pubspec.yaml`：删 `video_player_win`，加 `video_player_media_kit` + `media_kit`
+ `media_kit_video` + **`media_kit_libs_windows_video`**（只 Windows，不用全平台 meta 包）。
`main.dart` 首行：`VideoPlayerMediaKit.ensureInitialized(windows: true);`
**业务代码一行没改** —— `player_page.dart` 仍只写 `VideoPlayerController`。

### 顺带修的真 bug（hls_proxy.dart）
旧代理把 `#EXT-X-KEY` 原样透传，`URI="enc.key"` 是相对路径，播放器拼成
`http://127.0.0.1:<port>/hls/<tok>/enc.key` → 落到「清单」分支，
**把 178KB 的 m3u8 当 16 字节密钥返回** → 解密必失败。
修法：代理侧 AES-128-CBC 解密 + 从清单摘掉 KEY tag，播放器永远拿明文 TS。
- `_Seg` 记录 keyUrl/iv；`_Session.addSegment(url, keyUrl:, iv:)`
- `keyAttr()` 分隔符必须含**冒号**（`#EXT-X-KEY:METHOD=` 是冒号分隔），
  只写 `(?:^|,)` 会导致 METHOD 永远取不到 → 同样的病换个地方犯
- IV 缺省时按 RFC 8216 §5.2 用 media sequence 推导
- 新增 `test/hls_aes128_test.dart` 11 项

### 代理层为什么保留（重要，别删）
libmpv 走 FFmpeg 自己的 network.c，**不读 Windows 系统代理**。
云影/低调/极速/4K影视 四源必须挂代理 → 裸交给 libmpv 会直连 → 转圈。
经代理转发时取流走 Dart HttpClient，NetProxy 已装系统代理 —— 唯一通道。

## 1. 可可影视挑战页（最花时间，根因反直觉）

### 先排除的结论
PoW 算法**一直是对的**。实测前缀 `4388CE1B...`、`n1=4`、`i=224064`（897ms），
`sha1(前缀+i)=7aa9cbe3**b00b**08ef...` 第 4/5 字节正好 `0xb0/0x0b`，
Python hashlib 独立复算一致，且 224064 是最小解。挑战页结构与 11-11 相比**未变**
（仍 850 + `a0_0x2a54` 三元素数组 + `0x178` 旋转）。

### 真根因：Cookie 绑定 TCP 连接，而 Dart 收到 850 就丢连接
| 客户端 | 做法 | 通过率 |
| --- | --- | --- |
| Python 裸 socket | 同一条 CONNECT 隧道走完 挑战→解PoW→重发 | **4/4** |
| curl | 每次新进程（必然新连接） | **5 次偶然过 1 次** |
| Dart HttpClient | 同一实例串行两次，指望 keep-alive | **稳定失败** |

决定性证据：`connectionInfo.localPort` 第一次 **5571**、第二次 **5573** —— 端口变了，
连接没被复用。同一 Cookie 换新连接通过率仅 **1/4**，**延迟 1 秒即失效**。

### 改法
绕开 HttpClient，用 `SecureSocket` 自己拼 HTTP/1.1，钉住一条连接：
「建连 → 过闸 → 后续所有请求」全在同一条上。自带 gzip/deflate/chunked 解码。
`_PinnedChannel` 用 `_tail` 串行化（一条连接不能并发）。

顺带修：搜索 `t` 令牌有两个来源（隐藏 input 与链接 `&t=`，值相同仅编码不同），
不带 → `找到 0 部`，带 → `找到 90 部` / 18 锚点。

### 实测
首页 200 / 227,293B / **86 锚点**；搜索 庆余年/仙逆/谷雨 各 **18 锚点**；
分类连续剧 **48 锚点**；同实例连续 4 次全过。

## 修复「越刷越超时、重开秒出」——超时不取消请求导致连接泄漏（v1.10.7）

### 用户线索里的决定性判据

「一直刷新都出不来，但是关闭 app、重新打开，秒出」+「偶尔多次快速切换线路，
如果一条线路一直转圈出不来画面，我返回后下拉刷新分组列表，就会超时」。

**「重开就好」= 进程内资源泄漏。** 网络侧问题（断网/DNS/源站挂/限流）不会
因为重启 App 自愈；只有进程一退出就还给系统的东西才会这样。

### 逐项实测排除（记录成表，避免以后重复排查）

| 假设 | 实测 | 结论 |
| --- | --- | --- |
| 接口不可达 | 两 IP 各 10 次全 200，connect 33-50ms | 排除 |
| 连续请求变慢 | 连续 20 次 fail=0，median 510ms | 排除 |
| 源站并发限流 | 1/5/10/20/40 并发全成功 | 排除 |
| 连接池被占满 | dio 只缓存一个 HttpClient，maxConnectionsPerHost 默认 null（不限） | 排除 |
| keep-alive 死连接 | 原生 socket 实测服务端空闲 120s 不断 | 排除 |
| baseUrl 被改写 | 全项目仅声明处一处赋值 | 排除 |
| 明文流量被拦 | 已开 usesCleartextTraffic | 排除 |

### 真根因：`.timeout()` 只让等待方放弃，不取消底层请求

Dart 的 Future 没有取消语义。旧写法 `_postOnce(...).timeout(remain)` 之后，
Dio 请求和它的 socket 仍然活着。每失败一次漏一条连接 → fd / NAT 会话表攒满
→ 新 SYN 进不去 → connect 卡满 8s → connectionTimeout →「连接超时，请检查网络」。

**证据**（`test/api_cancel_on_timeout_test.dart`，本地 ServerSocket 只收不回，
统计服务端认为还开着的连接数）：修前连续 5 次超时 → `Actual: <5>`；修后 → 0。

### 修复：每次尝试独立 CancelToken，异常路径无条件 cancel

```dart
final token = CancelToken();
try {
  return await _postOnce(path, params, token).timeout(remain);
} catch (e) {
  if (!token.isCancelled) token.cancel('attempt ${attempt + 1} aborted: $e');
  ...
}
```

**不能全程共用一个 token**：一次 cancel 之后同一 token 上的后续请求会被 dio
立刻拒掉，重试直接失效。

三处同类写法全部修：`api.dart::_post`、`maccms_api_source.dart::_get`、
`site_http.dart::get`（`_once` 加 `CancelToken? token`，只给 Dio 分支，
钉住通道不需要——它不经过 Dio 也不共享连接池）。

**确认安全无需改的**：yuny/kanju/ddys/jisu/kvm4k/danmaku 只用 dio 内建超时
（`io_adapter.dart` 到点会 `request.abort()`，真的掐断）；hls_proxy 三处、
dlna 两处都在 `finally` 里 `client.close(force: true)`；download.dart 自带 cancelToken。

### 播放页：快速切线路导致 controller 永久泄漏

`_resolve` 原来**没有代次保护**（只有 `_resolving` 布尔，且没当锁用）。
换源按钮无节流，连点会并存多个流程；后完成的把 `_ctrl` 覆盖成自己的，
先完成的那个失去所有引用、永远不 dispose，解码器 + socket 全泄漏。

新增 `_playGen`：`_resolve` 开头 `++_playGen`，每个 await 返回点核对；
`_startPlay(url, gen)` 在 `initialize()` 后、赋值 `_ctrl` 前核对，作废时
**自己 dispose 刚建的 controller**；catch 分支也被拦住（否则旧流程的失败
会冲掉新线路的加载态）；`dispose()` 里 `_playGen++`。`_loadDanmaku(gen)` 同步加。

### 新增静态守卫（防以后加源时再踩）

`test/net_resource_leak_guard_test.dart`：扫 lib 全部源码，检查
① `Dio(` + `.timeout(` 的文件必须同时有 `CancelToken` 和 `.cancel(`
② 创建 `HttpClient()` 的文件必须有 `close(force: true)`
③ 钉住关键出口存在且带取消机制（防止前两条因改名静默通过 = 假绿）

做过**反向验证**：删掉 api.dart 的 `token.cancel(...)`，守卫立刻报
`lib/core/api.dart (CancelToken=true, cancel()=false)`。
读取时剔除注释行——`net_proxy.dart` 注释里就写着 HttpClient() 工厂，不剔除会误报。

### 踩到的坑

1. **测试里固定 sleep(600ms) 等连接关闭是不稳的**。连接关闭是异步链：
   abort → FIN/RST → 内核通知 accept 侧 → Dart 排 onDone。机器空闲几十毫秒，
   跑全量测试时 CPU 占满会拖到几百毫秒，偶发 `+502 -1`。改成**轮询**
   （`waitUntilClosed`，10ms 一次最多 5s），快时 10ms 返回，慢时也等得到。
2. **`expect` 不能写在 `test()` 外面**，否则 `OutsideTestException` 让整个
   文件加载失败。文件级读取放 `setUpAll`。
