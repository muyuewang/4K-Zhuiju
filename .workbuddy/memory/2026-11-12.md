## v1.10.1：三个数据源故障 + 播放器黑底黑字（已发布）

- 提交 `c254333`，tag `v1.10.1`，main `47f5d4f..c254333`
- Release: https://github.com/muyuewang/4K-Zhuiju/releases/tag/v1.10.1
- 资产：APK 58,899,096 B (md5 e39cf19b…)、zip 12,769,328 B (md5 4ec97fa0…)
- 版本 1.10.0+17 → 1.10.1+18；306 项测试全绿

### 核心发现：Dart 的 HttpClient 不读系统代理

浏览器读 Windows 系统代理（`ProxyEnable`/`ProxyServer`），`dart:io` 的
`HttpClient` **从不读**，永远直连。这一条同时解释了「暴风封面加载不出」和
「可可影视列表加载不出」——两者网页版都正常。

**排查陷坑（重要，别再犯）**：用 Python `urllib` 探测会得到完全相反的结论，
因为它**自动读系统代理**。早期所有「暴风封面 200、可可 850，服务端没问题」的
结论都是错的。必须加 `ProxyHandler({})` 强制直连，才能模拟 App 的真实行为。

修法：`core/net_proxy.dart`，在 `HttpOverrides.global` 单点注入
（覆盖 8 个 Dio、裸 HttpClient、HlsProxy、cached_network_image 内部的
package:http、video_player）。
- 本机/内网段强制 DIRECT —— HlsProxy 监听 127.0.0.1，代理它会死循环
- 端口候选表**刻意不含 8080/1080**（本机开发服务器常占，误判比不设代理更糟）
- 认出端口后发 `CONNECT 127.0.0.1:1` 验证协议
- reg.exe 读不到时扫候选端口兜底（本环境 reg 被沙箱拦，正好验证了这条路径）

### 片库转圈：HlsProxy 把子清单当分片

片库 4K 的 master 只有 101 字节 1 个条目，实为**子清单**。旧代码一律当分片
转发 → 子清单里的相对地址以 127.0.0.1 为基址拼错 → 永久转圈。
修：识别 m3u8 递归展开 + `playlistDepth` 上限 32 + `addSegment` 去重。
实测展开 2680 条，分片 206/262144B 全正常。

### 播放器黑底黑字（同一根因）

宽屏右栏、AppBar、本地播放页控制面板、竖屏选集弹层底色恒深色，文字却继承
浅色主题 `onSurface(#14161A)`，对比度 1.06:1。
- 新增 `kVideoTheme`（恒深色 ThemeData，`static final` 缓存）套住整块恒黑区域
- AppBar 补 `foregroundColor: Colors.white` + 中文 tooltip
- 逐个 Text 补色治不住后续新增控件，套主题才是一劳永逸

### Windows 构建（避坑，复发过多次）

`flutter build windows` 报 "Unable to find suitable Visual Studio toolchain"，
但 VS2022 实体齐全（缺的是 workload 标记）。继续用：
1. `cmake --build build/windows/x64 --config Release --target INSTALL`

3. **验证新代码进产物**：中文常量在 AOT 里不是明文，`strings` 搜不到别误判。
   用 ASCII 标识比对：`net_proxy`/`kVideoTheme`/`findProxyFor` 旧包 False、新包 True

## v1.10.2：播放器控制条 + 双全屏 + 批量下载 + 下载归档

### AppBar 图标「还是看不到」的真凶

上一轮只写了 `foregroundColor: Colors.white`，用户反馈仍不可见。
根因在 Flutter `app_bar.dart` 的取值顺序：
`widget.iconTheme ?? appBarTheme.iconTheme ?? defaults.iconTheme!.copyWith(color: foregroundColor)`
本项目 `theme.dart` 钉了 `appBarTheme.iconTheme`，所以 `foregroundColor` **被完全跳过**。
修：两个播放页都补 `iconTheme` + `actionsIconTheme: IconThemeData(color: Colors.white)`。
**这是本项目第一次真正构建 AppBar 读解析后颜色**，静态扫源码抓不住「写了但没生效」。

### 控制条三行压一行（B 站样式）

- `player_controls.dart` 新增 `static const double _barH = 40`，原 `Column`（进度+42dp 按钮行，连边距约 100dp）改单行 Row
- 宽 ≥400dp 才显示倍速/音量（`LayoutBuilder` 判 `cons.maxWidth`），窄屏只留 播放·进度·时间·全屏
- `Slider.padding: EdgeInsets.symmetric(vertical: 2)` 压掉默认 overlay 留白；
  `year2023` 已废弃，改用 `RectangularSliderTrackShape` + `SliderTheme`（**不要再传 year2023**）
- 仍走浮层 + 点屏显隐，**不是**独立占一行。上一轮改成占行被用户用 B 站截图否掉

### 竖屏/横屏双全屏

- `platform.dart`: `setFullscreen(bool on, {bool portrait = false})`，竖屏锁 `portraitUp`，横屏锁 `landscapeLeft/Right`，都配 `immersiveSticky`
- `_pickFullscreenPortrait()` 判据 `aspectRatio < 1.0`（**阈值取 1.0 不是 9:16**，让 4:3 老片仍走横屏）
- 全屏顶部栏加方向切换按钮，`isMobile` 才显示

### 选集多选批量下载

- 入口：侧栏面板标题栏「批量」+ 长按任意格子；竖屏弹层同样有一套
- 勾选态 = 主色描边 + `alpha .22` 淡底 + 12px `check_circle`，与「正在播放」实心橙区分
- 关键：**地址必须逐集解析**，只入队不预解析（几十集串行解析要几分钟，界面会像卡死）
- `_enqueueDownloads` 抽成共用方法：侧栏和弹层各自维护勾选状态（弹层是独立 route，够不到页面 setState），但入队逻辑必须一致，否则两处下载会落进不同目录
- `_batchBar()`（侧栏）+ `_sheetBatchBar()`（弹层），0 集时按钮置灰而非弹 toast

### 下载按剧集归档

- 磁盘：`downloads/<剧名>/第01集.mp4`；`DownloadTask` 加 `group` / `fileBase`
- 下载页分组显示：组头（剧名+集数+已完成+下载中，可折叠，带「删除整组」）+ 组内短标题
- 分组逻辑下沉到 `download.dart` 做纯函数：`groupOfTitle` / `groupKeyOf` / `shortTitleOf` / `groupTasks` / `DownloadGroup`
- **老任务不迁移**（`group` 空串、`filePath` 指回平铺位置），显示层从 title 反推兼容

### 分目录带出的隐患（本轮自己发现的）

`_adoptOrphanFiles` 原来只 `dir.list()` 顶层。文件进子目录后，索引一旦损坏/被清理，
子目录成品永远收编不回来 → 界面「暂无下载任务」而磁盘躺着几个 G。
修：`list(recursive: true)` + 从父目录名反推 `group` + id 用「组名_文件名」防跨剧撞名。
