# 数据源插件化评估

> 目标：源失效 / 抓取规则变更时，不用重新发版，用户通过 URL 导入新规则即可。  
> 评估对象：远程执行 Dart（`dart_eval`）方案。  
> 结论日期：基于 dart_eval 0.8.5 + Dart SDK 3.13.7 实测。

---

## 〇、后续：已改用 QuickJS（2026-11-17 实施）

**这份文档评估的是 dart_eval 路线。实际落地时换成了 QuickJS（`flutter_js`）。**  
两个引擎的结论不能互相引用，所以先看这张对照表，再决定要不要读下面的 dart_eval 细节。

| 能力                                | dart_eval              |   | QuickJS（实际采用）                            |
| --------------------------------- | ---------------------- | - | ---------------------------------------- |
| `async` / `await` / `Promise`     | ❌ 裸 async **静默返 null** |   | ✅ 真能用（`await Promise.resolve(99)` → 100） |
| `x == null` 判空                    | ❌ 恒返 false（语义错误）       |   | ✅ 正常                                     |
| `Map.forEach` / 扩展方法 / `continue` | ❌ 不支持                  |   | ✅ 支持                                     |
| 正则 / JSON / 中文 / emoji            | ✅                      |   | ✅                                        |
| 宿主 ⇄ 脚本双向消息                       | 需自己注入闭包                |   | ✅ 内置 `sendMessage`                       |
| 沙箱逃逸（`require` / `fs`）            | 需 Runtime 权限控制         |   | ✅ 天然没有（QuickJS 无这些全局对象）                  |
| **死循环能否中止**                       | 靠 isolate kill         |   | ❌ **中止不了**，见下                            |

**唯一比 dart_eval 更差的一点**：QuickJS 的死循环**宿主杀不掉**。实测：

- `QuickJsRuntime2(timeout: 1)` 跑 `while(true){}`，**89 秒后仍未返回**（timeout 参数没接线）
- `Isolate.kill()` 对它也无效：15 秒收不到退出信号，后台线程继续空转

所以插件系统的安全设计不能依赖「超时打断」，改成三道前置防线：

1. **装载前静态筛查** `while(true)` / `for(;;)`（`looksLikeInfiniteLoop`）
2. **强制入口同步**，返回 Promise 直接拒绝（顺带堵住「插件自己发请求绕过 SSRF 防护」）
3. **中毒计数**：超时一次换一个 worker，累计 2 次就停用插件执行

实现见 `code/flutter_app/lib/core/plugin/`，配置见 `config/plugins/`，  
作者向文档见 `config/plugins/README.md`。

**下面第一～八节是 dart_eval 的原始评估，保留作技术记录，不要再据此选型。**

## 一、结论

**方案可行，但不能按「让插件写 async 代码」的方式做。**

dart_eval 的 `async/await` 基本不可用，而现有 `DataSource` 接口（`search` / `category` / `detail` / `resolveUrl`）全是 `Future`。直接照搬会撞死在第一行。

可行的形态是：

```
宿主负责所有网络 IO（异步，用现有 http 栈）
        ↓ 把响应体作为纯字符串交给插件
插件只做同步解析（纯函数，无 IO、无 Future）
        ↓ 返回 JSON 字符串
宿主反序列化成 Drama / DramaDetail / String
```

也就是 **「宿主 fetch + 插件同步解析」**。这条路径已在探针里跑通：3 接口全链路、19 份规格并发编译、190 次解析全成功。

另有三个必须处理的硬约束：

1. **插件里不能出现 null**。dart_eval 的 null 语义是坏的（见下表），必须由宿主注入 `gs` / `gi` / `gl` 三个取值函数，永远返回非 null 默认值。
2. **必须放独立 isolate 跑**。`executeLib` 是同步阻塞调用，插件写死循环宿主无法中断。
3. **必须提供「安全方言」文档**。`continue`、标签跳转、`Map.forEach`、扩展方法、`switch 表达式` 都不支持，作者踩坑成本高。

## 二、dart_eval 能力边界（全部实测）

### 2.1 致命：null 语义错误

这一组是最危险的，因为 **`x == null` 不崩溃但结果错**，静默出错比崩溃更难查。

| 写法                       | 预期     | 实测        | 结论                                           |
| ------------------------ | ------ | --------- | -------------------------------------------- |
| `x == null`（x 确实是 null）  | true   | **false** | ❌ 语义错误                                       |
| `x != null`（x 确实是 null）  | false  | **true**  | ❌ 语义反向                                       |
| `x ?? "默认"`（x 是 null）    | "默认"   | **null**  | ❌ 不兜底                                        |
| `x is String`（x 是 null）  | false  | **运行时崩溃** | ❌ `type 'Null' is not a subtype of '$Value'` |
| `x.toString()`（x 是 null） | "null" | **运行时崩溃** | ❌                                            |
| `x == null ? a : b`      | b→a    | **运行时崩溃** | ❌                                            |

结论：**插件内一律不准碰可能为 null 的值**。这不是风格建议，是硬性要求。

### 2.2 语法支持情况

| 语法                                                                        | 状态 | 说明                                                       |
| ------------------------------------------------------------------------- | -- | -------------------------------------------------------- |
| `for (var i = 0; ...)` 索引循环                                               | ✅  | 推荐用法                                                     |
| `for (final x in xs)`                                                     | ✅  | 元素需保证非 null                                              |
| `break`                                                                   | ✅  |                                                          |
| `continue`                                                                | ❌  | `Unknown statement type ContinueStatementImpl`           |
| 标签跳转 `outer:`                                                             | ❌  | `LabeledStatementImpl`                                   |
| `switch` 语句                                                               | ✅  |                                                          |
| `switch` 表达式                                                              | ❌  |                                                          |
| `try/catch`                                                               | ✅  | 推荐用于 `jsonDecode`                                        |
| 扩展方法                                                                      | ❌  | 运行时崩溃                                                    |
| 闭包 / lambda                                                               | ⚠️ | 简单形态可用，复杂签名报 `FunctionPtr: Cannot invoke`                |
| `Map<K,V>()` 构造器                                                          | ❌  | `Class "Map" does not have a default constructor`        |
| `{...}` map 字面量                                                           | ✅  | **必须用字面量代替构造器**                                          |
| `[...]` list 字面量                                                          | ✅  |                                                          |
| 集合 if / 集合 for                                                            | ❌  | `type 'Null' is not a subtype of '$Value'`               |
| `!expr`（dynamic 类型）                                                       | ❌  | `Unary prefix "!" is currently only supported for bools` |
| `Map.forEach`                                                             | ❌  | `UnimplementedError: $Object.forEach`                    |
| `RegExp` / `hasMatch` / `firstMatch`                                      | ✅  |                                                          |
| `jsonDecode` / `jsonEncode`                                               | ✅  | 需在插件内 `import "dart:convert"`                            |
| `split` / `substring` / `replaceAll` / `padLeft` / `trim` / `toLowerCase` | ✅  | **需静态类型标注为 String**，否则 `Unknown method int.trim`         |
| `Uri.parse`                                                               | ✅  |                                                          |
| `base64Decode`                                                            | ❌  | `Could not find declaration`                             |
| `package:crypto`                                                          | ❌  | 不能 import                                                |
| `async` / `await` / `Future.value`                                        | ❌  | 裸 async **静默返回 null**，不报错                                |

### 2.3 沙箱边界（Security）

`Runtime` 默认**零权限**。实测逃逸情况：

| 尝试                                                    | 结果                                          |
| ----------------------------------------------------- | ------------------------------------------- |
| `import "dart:io"`                                    | ⚠️ **可以 import**                            |
| `File("x")` 构造                                        | ⚠️ 可以构造                                     |
| `File.readAsStringSync()`                             | ✅ 被拦 `Permission 'filesystem:read' denied`  |
| `File.writeAsStringSync()`                            | ✅ 被拦 `Permission 'filesystem:write' denied` |
| `HttpClient().getUrl(...)`                            | ✅ 被拦 `Permission 'network' denied`          |
| `Platform.environment`                                | ✅ 编译期拒绝                                     |
| `Process.runSync(...)`                                | ✅ 编译期拒绝                                     |
| `import "dart:isolate"` / `dart:ffi` / `dart:mirrors` | ✅ 编译期拒绝                                     |
| `import "package:*"`（任何第三方包）                          | ✅ 编译期拒绝                                     |

权限可按粒度授予（这点很好）：

```dart
rt.grant(NetworkPermission.url('https://api.example.com'));
rt.grant(FilesystemReadPermission.directory('/tmp/cache'));
rt.grant(ProcessRunPermission.namedExecutable('ffmpeg'));
```

**我们的策略：一个权限都不给。** 宿主导入的 `gs`/`gi`/`gl` 是纯内存取值，插件不碰 IO、不联网，沙箱保持默认全关。

### 2.4 性能

| 项目                | 实测         |
| ----------------- | ---------- |
| 单份插件冷编译           | 15–25 ms   |
| 19 份冷编译           | 290–483 ms |
| 单次解析（10 条列表）      | 0.9–1.4 ms |
| 190 次解析           | 172 ms     |
| 1000 次 while 循环   | 3 ms       |
| 100000 次 while 循环 | 151 ms     |

解释器比 AOT 慢约 50–100 倍，但列表解析（10 条 1.4ms）完全够用。编译开销应做**内存缓存 + 磁盘缓存**（按插件内容 hash 缓存 EVC 字节码）。

**死循环风险**：`executeLib` 同步阻塞，宿主无法中断。10 万次循环 151ms，100 万次约 1.5s，1000 万次约 15s。必须放独立 isolate 并设超时（建议 3 秒），超时直接杀 isolate。

## 三、架构方案

### 3.1 分层

```
┌─────────────────────────────────────────────┐
│ UI（搜索 / 分类 / 详情 / 播放）              │
└───────────────┬─────────────────────────────┘
                │ 仍走 DataSource 的 Future 接口
┌───────────────▼─────────────────────────────┐
│ RemotePluginSource implements DataSource     │  ← 新增，只有这一个类
│  ├ search/category/detail  → 组装 ctx        │
│  ├ resolveUrl              → 多轮状态机      │
│  └ 所有 Future 在宿主侧完成                  │
└───────────────┬─────────────────────────────┘
                │ 同步调用（隔离 isolate）
┌───────────────▼─────────────────────────────┐
│ PluginRuntime                                │
│  ├ EVC 编译缓存（hash → bytecode）           │
│  ├ 注入 gs/gi/gl 闭包                        │
│  ├ 超时保护（3s，超时杀 isolate）            │
│  └ 异常收敛 → 返回 __error，不抛给 UI        │
└───────────────┬─────────────────────────────┘
                │
┌───────────────▼─────────────────────────────┐
│ 插件脚本（远程 URL 下载，纯同步解析）        │
│  ├ listItems(body, srcId, gs, gi) → JSON     │
│  ├ detailItem(body, srcId, gs, gi) → JSON    │
│  └ step(ctxJson, gs, gi) → 指令 JSON         │
└─────────────────────────────────────────────┘
```

### 3.2 插件接口（只有 3 个，全部同步）

```dart
// 1. 列表（搜索和分类共用一个，靠 url 区分）
String listItems(String body, String srcId, Function gs, Function gi);

// 2. 详情
String detailItem(String body, String srcId, Function gs, Function gi);

// 3. 多轮状态机（用于需要「先列表后详情」或需要 token 的源）
String step(String ctxJson, Function gs, Function gi);
```

返回值统一是 **JSON 字符串**（不是 Map）。原因：`Map` 跨边界要 unwrap `$Map<$Value,$Value>` 嵌套，容易出错；字符串最稳。

返回格式：

```json
// listItems
{"items":[{"id":"101","name":"剧A","pic":"http://...","remark":"更新至10集"}],"page":1}

// detailItem
{"id":"101","name":"剧A","content":"简介",
 "lines":[{"line":"m3u8","episodes":[{"name":"第1集","url":"http://..."}]}]}

// step（多轮）
{"need":"fetch","url":"https://api/list?pg=1","method":"GET"}
{"done":{...}}   // 结束
```

### 3.3 宿主辅助函数（关键设计）

这是绕开 null 缺陷的核心。插件里**所有取值都走这三个函数**，它们永远返回非 null：

```dart
gs(map, "key")  → String   缺失/null 时返回 ""
gi(map, "key")  → int      缺失/null/非数字时返回 0
gl(map, "key")  → List     缺失/非列表时返回 []
```

插件作者写：

```dart
final name = gs(it, "vod_name");   // 永远不会是 null
final id = gi(it, "vod_id");       // 永远不会是 null
```

而不是：

```dart
final name = it["vod_name"] as String;  // 可能 null，后续一碰就崩
```

### 3.4 安全方言清单（写进文档给作者）

```
禁止：
  ✗ x == null / x != null / x ?? y / x is T   （x 可能为 null 时）
  ✗ continue / 标签跳转 / switch 表达式 / 扩展方法
  ✗ Map<K,V>() 构造器 / Map.forEach / 集合 if / 集合 for
  ✗ async / await / Future
  ✗ import 任何 package:（只允许 dart:convert）

必须：
  ✓ 只用 gs/gi/gl 取值
  ✓ Map/List 用字面量 {...} / [...]
  ✓ 循环用 for (var i = 0; ...) 或 for-each（元素保证非 null）
  ✓ 字符串里的 $ 写成 \u0024
  ✓ jsonDecode 包在 try/catch 里
  ✓ 字符串方法前先声明 String 静态类型

替代写法：
  continue      → if 包裹
  Map.forEach   → for (final k in m.keys)
  x == null     → 用 gs 取值代替
```

### 3.5 安全设计

插件 URL 导入 = 用户可以往 App 里塞任意代码，必须防。

| 风险               | 对策                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 插件读文件 / 联网 / 起进程 | Runtime 权限全关（实测默认就是关的）                                                                                                    |
| 死循环冻结 App        | 独立 isolate + 3s 超时强杀                                                                                                      |
| SSRF（插件让宿主请求内网）  | 宿主 fetch 层做 **URL 白名单校验**：禁 `127.0.0.1` / `10.` / `192.168.` / `172.16-31.` / `169.254.` / `localhost` / `file://`；禁跳转到这些 |
| 响应体撑爆内存          | fetch 层限 5MB，超限截断                                                                                                         |
| 恶意插件拿用户 IP       | 提示用户「只导入你信任的来源」，首次导入弹确认                                                                                                   |
| 插件更新被中间人篡改       | URL 走 HTTPS；清单文件可带 sha256，变了就提示                                                                                           |

## 四、现状盘点：13 个源可迁移，6 个不行

之前统计过 19 个源的结构：

| 类型                             | 数量 | 可插件化             |
| ------------------------------ | -- | ---------------- |
| `MacCmsApiSource`（纯 JSON 配置驱动） | 12 | ✅ 全部可            |
| `MacCmsSource`（HTML 正则驱动）      | 1  | ✅ 可（RegExp 已验可用） |
| 独立实现                           | 6  | ❌ 不能纯脚本化         |

`maccms_api_source.dart` 1159 行里**零处站点特判**，纯配置驱动，这 13 个（68%）迁移成本很低。

剩下 6 个为什么不行：

| 源                   | 依赖                            | 能否脚本化                                           |
| ------------------- | ----------------------------- | ----------------------------------------------- |
| 橘汁                  | AES + protobuf + RSA 解密       | ❌ `package:crypto` 不能 import，`base64Decode` 都没有 |
| 看剧                  | 两阶段 resolve（需 token 交换）       | ⚠️ 多轮状态机可覆盖，但要实测                                |
| 4K影视 / 极速 / 云影 / 低调 | `CdndefendGate` 连接钉住 + PoW 计算 | ❌ 需要 async + 自定义 HTTP 栈 + 大计算量                  |

**结论：这 6 个保持内置硬编码。** 它们的复杂度和反爬强度本身就决定了不能被简单脚本描述，这正是它们需要写代码的原因。插件化机制不该为它们牺牲安全性。

## 五、分期落地

### Phase 1（建议先做，工作量约 2–3 天）

- `PluginManifest` 数据模型（id / 名称 / 版本 / 脚本 URL / sha256 / 分类配置）
- `PluginRuntime`：EVC 编译 + 缓存 + isolate 隔离 + 超时 + `gs/gi/gl`
- `RemotePluginSource implements DataSource`（3 接口 + 多轮 step）
- 设置页「自定义源」入口：URL 导入、列表、启用/禁用、删除、更新
- 宿主 fetch 层 SSRF 防护 + 大小限制
- 内置 13 个 MacCMS 源改写成插件脚本（bundle 在 assets 里，走同一条加载路径，这样能验证机制等价性）

### Phase 2（Phase 1 稳定后）

- 插件清单托管（一个静态 JSON 索引，用户可一键添加）
- 插件调试面板（粘贴脚本 + 粘贴响应体，直接看解析结果）—— 这个对生态很关键
- 失败自动禁用（连续 N 次解析失败标记为可疑，提示用户）

### Phase 3（可选）

- 支持插件声明 UA / Referer / 超时，宿主 fetch 时带上
- 支持 XML 格式解析（现在 `MacCmsFormat` 有 xml，插件侧要提供 `gx` 辅助函数）

## 六、与 TVBox 方案的对比

| 维度     | TVBox       | 本方案                         |
| ------ | ----------- | --------------------------- |
| 远程代码载体 | jar / 远程 JS | Dart 脚本（dart_eval）          |
| 沙箱     | 基本没有        | Runtime 默认零权限，实测拦得住文件/网络/进程 |
| 作者门槛   | 会写 Java/JS  | 会写 Dart（有安全方言约束）            |
| async  | 支持          | ❌ 不支持，改为宿主 fetch + 同步解析     |
| 能力上限   | 高（能写任意逻辑）   | 中（纯解析 + 宿主 IO）              |
| 风险     | 恶意插件可做任何事   | 受控，最坏是解析出错或超时               |

TVBox 生态强是因为能力上限高，代价是安全性基本为零。我们走窄一点，换来的是插件跑在沙箱里、用户导入不用赌命。

## 七、残留风险

1. **作者学习成本**：安全方言约束不少，写错会得到很晦涩的错误（`type 'Null' is not a subtype of type '$Value'`）。必须配调试面板，否则生态起不来。
2. **async 缺失是硬伤**：需要「先请求 A 拿 token 再请求 B」的源要走多轮 `step`，比直接写 async 啰嗦。已验可行，但作者体验一般。
3. **is 判断可能为 null 的值会崩**：这条最容易踩，因为 Dart 里 `x is String` 是本能写法。
4. **dart_eval 版本依赖**：要求 SDK `>=3.8.0`（本项目 3.13.7 满足）。它依赖 `analyzer ^8.2.0`，未来 Dart 大版本升级时可能需要跟版本。
5. **6 个源仍需发版**：这是设计上的取舍，不是缺陷。但用户预期要管理好——README 里得写清楚「哪些源支持插件更新，哪些必须等版本」。
